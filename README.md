# NEON LEAP · 霓虹跃迁

> **在线试玩：https://x-lsh.github.io/neon-leap/**
>
> 打开就能玩，不用安装、不用登录、没有后端。

一个跑在浏览器里的**精确平台跳跃游戏**。Celeste 式的操作手感，霓虹矢量的视觉语言，零构建、零依赖、零后端。

> 青色的东西是你的，品红色的东西要你的命。

---

## 这是什么

- **八向冲刺 + 墙跳 + 抓墙**，没有二段跳 —— 空中机动全靠冲刺，动词少而深。
- **15 关手工关卡**，分五个章节，每关只教一件事，然后开始组合。
- **翻越**：爬到墙沿会自动翻上去。不需要额外按键 —— 手感和跳跃保持一致，才不用为它写教程。
- **音效全部实时合成**，零音频文件。第一个音在按下按键的那一帧就响。
- **存档在浏览器本地**：关卡进度、每关最佳时间、累计死亡数。没有账号，也没有云端。
- **不用安装任何东西**，打开链接就能玩。

## 操作

| 动作 | 键位 |
| --- | --- |
| 移动 | `←` `→` 或 `A` `D` |
| 跳跃（长按更高） | `Z` / `空格` / `K` |
| 冲刺（八向） | `X` / `J` / `Shift` |
| 抓墙（消耗耐力） | `C` / `L` / `Ctrl` |
| 爬墙 / 攀爬方向 | `↑` `↓` 或 `W` `S` |
| 重开本关 | `R` |
| 退出本关 | `Esc` |
| 切换调试面板 | `F1` |
| 静音 | `M` |
| 调试：跳到下一考区 | `]` / `[` |

关卡选择：方向键移动，`Z` 或回车进入。**鼠标点卡片也能进。**

## 手机上也能玩

触屏 UI 只在触屏设备上出现，桌面端**一行都不会多**。

- **左半屏**：浮动摇杆。按在哪里哪里就是原点，不画固定底盘。
  手指拖出 46px 后原点跟着走 —— 因为手指在屏幕上只有那么大一块地方，
  原点焊死的话滑到边缘就再也推不出满偏，而「推不出满偏」在平台跳跃里等于「跑不到最高速」。
- **右下角三颗键**：跳跃（最大）、冲刺、抓墙。**左上角**：返回 / 重开 / 音效，
  故意放在拇指够不着的地方 —— 误触的代价（瞬间退出本关）远高于便利性。

> **为什么是 3 颗而不是 2 颗？**
> 初稿担心「一个拇指按不过来」，但墙跳在 `player.js` 里的两个分支
> （抓着墙 / 只是贴着墙下滑）产出的速度**逐字相同**，
> 所以「松开抓墙再按跳」和「按住抓墙按跳」是同一个动作，没有损失。
> 反过来，把抓墙做成「长按跳跃」需要约 150ms 消歧 ——
> 对一个每关要用几十次的核心动词来说，玩家会感觉指令被吞掉了。

## 三条手感规则

这个项目的手感不是靠"感觉"调出来的，而是三条可以断言的规则：

1. **输入永不丢失** —— 土狼时间（0.10s）+ 跳跃缓冲（0.12s）同时存在。玩家在落地前按下的跳跃，落地瞬间必须起跳。
2. **可变跳跃高度** —— 长按减重力，松键速度按 0.5 倍衰减。跳跃高度是玩家的表达旋钮，不是固定值。
3. **死亡必可归因** —— 所有杀伤判定框必须与视觉体积一致。不存在"我明明没碰到"的死亡。

## 本地运行

零依赖，不需要 `npm install`。但 ES Modules 需要 HTTP 协议（`file://` 会被浏览器拦截），所以起一个静态服务器：

```bash
node scripts/serve.mjs      # → http://127.0.0.1:5173/
```

## 验证

不需要「看它能不能跑」——验证是脚本化的，而且**能在线上地址上重跑**：

```bash
node scripts/verify.mjs                  # 247 项纯逻辑断言，不需要浏览器
node scripts/e2e.mjs                     # 65 项真实 Chrome + CDP 实测（本地）
APP_URL=https://x-lsh.github.io/neon-leap/ node scripts/e2e.mjs   # 同一套断言跑线上
node scripts/trace.mjs                   # 15 关可解性：重放通关策略并断言抵达出口
node scripts/abilities.mjs               # 玩家能力探针：实测每种机动的上限
```

`verify.mjs` 能脱离浏览器裸跑，是因为 `game/` 层完全不碰 DOM 与 Canvas —— 这是分层架构的直接红利，不是巧合。

**触屏也是被断言看守的，不是「手感上大概能用」**：
摇杆的 8 个方向与 45° 扇区边界、死区、动态重定位上限，全在 `verify.mjs` 里逐条问清楚
（这类 bug 在真机上要靠手指恰好停在边界上才复现，属于「偶发、难拍、说不清」的那种）；
浏览器端则用 CDP 的**真实触摸事件**驱动游戏，
并额外体检按键几何 —— 完整在视口内、该点最上层可命中、可点尺寸 ≥ 44px、三颗键互不重叠。

**关卡可解性怎么证明**：平台跳跃的状态空间是连续的，没法像华容道那样枚举。
所以每一关都配一条**确定性策略**（读世界状态、而非死记时序），
`trace.mjs` 重放它并断言抵达出口 —— 这是「存在一条通关路径」的构造性证明。
**15 关全部通过。**

**能力标尺必须实测**：`abilities.mjs` 会把每种机动的真实上限测出来，
关卡尺寸一律以它为准，而不是从配置值推算 —— 因为配置里的标称值经常和实际不符。

## 项目结构

```
src/
├── core/     引擎层：循环、输入、画布变换、音频、存储（不含任何游戏语义）
├── game/     规则层：物理、玩家状态机、世界、摄像机、粒子（纯逻辑，不碰 DOM）
├── render/   渲染层：调色板、伪辉光、背景（只读状态，不修改）
├── levels/   关卡数据：纯数据，零逻辑
└── scenes/   场景层：唯一同时接触输入、更新与渲染的地方
```

依赖严格单向：`scenes → game → core`。反向引用一律禁止。

## 关于性能的两个硬约束

- **禁止 `ctx.shadowBlur` 进渲染循环**。它是 Canvas 2D 里最贵的一个参数。霓虹感用「同一形状描 3 遍」的多层描边伪造 —— 成本只剩 3 次 `stroke()`。
- **对象池是硬要求**。粒子上限 400，热路径零对象分配。GC 抖动是低端设备掉帧的头号杀手。
